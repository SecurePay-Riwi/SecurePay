# System overview

Event-driven microservices, managed services first, in Ohio (`us-east-2`) across two Availability Zones.

![PagoSeguro architecture flow on AWS](/img/architecture-flow.jpg)

*The diagram labels are in Spanish. The data band in the middle (DynamoDB, Valkey, RDS, the e-mail topic and the Data Lake) is what every zone uses: above it, what happens with each transaction; below it, the daily loads, the rules and cases APIs, the night, the alerts and the dashboard; at the bottom, the order of the one `terraform apply`. The legend explains the colors. Drawn by `doc-website/diagrams/architecture_flow.py`.* <a href={require('@site/static/img/architecture-flow.jpg').default} target="_blank">Open full size</a>.

## In one paragraph

The wallet core sends each transaction over HTTPS to an **Application Load Balancer**, which spreads it across the **decision engine tasks on ECS Fargate** (FastAPI, 4 to 24 tasks). The engine reads and updates its state in **ElastiCache Serverless for Valkey** and is built to answer in under 200 ms (at 300 tx/s not yet in every minute: [known issue](../getting-started/load-test.mdx#known-issue)). It then publishes the decision to **SNS**, which copies it to **three SQS queues** (cases, history, analytics), each with its dead-letter queue and its **Lambda** consumer: cases and history write to **RDS PostgreSQL** (Multi-AZ), and analytics to the raw layer in **S3**. Spark jobs run on **AWS Glue 6.0 (PySpark)**; the nightly reconciliation and the analytics after it are orchestrated by **Step Functions + Lambda**, started by **EventBridge Scheduler**. The Data Lake has three layers (`raw`, `curated`, `analytics`), cataloged in **Glue Data Catalog**, queried with **Athena** and shown in **Power BI**. Analysts and the risk manager use **API Gateway + Lambda**; the evidence of closed cases goes to a separate S3 bucket with **Object Lock** and **Glacier Instant Retrieval**.

The step-by-step path of a transaction and everything that happens afterwards is in [Data flow](./data-flow.mdx).

## What each service does {/* #services */}

Grouped by layer. Why each one was chosen, and what was discarded, is in [AWS infrastructure](./infrastructure.mdx#services).

### Entry

| Service | Role in PagoSeguro |
| :--- | :--- |
| **Application Load Balancer** | The only entry from the wallet core. Terminates HTTPS on port 443 and spreads each transaction across the engine tasks in both zones, checking their health. |
| **API Gateway + Cognito** | Entry for people: analysts and the risk manager sign in with Cognito and use the rules and cases APIs. |

### Compute

| Service | Role in PagoSeguro |
| :--- | :--- |
| **ECS Fargate** | Runs the decision engine (FastAPI), 4 to 24 tasks across the two zones, and the on-demand admin task for migrations and the seed. |
| **Lambda** (12 functions) | Everything with low or irregular volume: the three queue consumers, the rules and cases APIs, the alerts task, the exchange rates and the cache load (accounts, merchants and the restricted list), the two reconciliation steps, the analytics export and the database bootstrap. |

### State and data

| Service | Role in PagoSeguro |
| :--- | :--- |
| **ElastiCache Serverless (Valkey)** | The engine's memory: idempotency keys, time windows, 24-hour sums, devices per account, active rules and the full restricted list. Replicated across zones. |
| **RDS PostgreSQL** (Multi-AZ) | Business data: users, accounts, devices, merchants, versioned rules, cases and reconciliation differences. It does not store transactions. |
| **DynamoDB** | The daily exchange rates, loaded by the engine at startup. |
| **S3 Data Lake** | Three layers: `raw` (decisions and partner statements as they arrive), `curated` (clean Parquet) and `analytics` (dimensional model for the dashboard). |
| **S3 evidence bucket** | Evidence of each closed case, locked with Object Lock in COMPLIANCE mode for 10 years, in Glacier Instant Retrieval. |

### Messaging

| Service | Role in PagoSeguro |
| :--- | :--- |
| **SNS** | The `decisiones` topic copies every decision to the three queues. Two more topics send e-mails: `alertas-negocio` to compliance, the supervisor and treasury, `alarmas-operativas` to the tech team. |
| **SQS** | Three independent queues (`casos`, `historial`, `analitica`), each with its dead-letter queue, so one consumer falling behind does not stop the others. |

### Processing and orchestration

| Service | Role in PagoSeguro |
| :--- | :--- |
| **AWS Glue 6.0** (PySpark) | The two Spark jobs: the reconciliation match and the analytics ETL (Data Lake layers, rule effectiveness, shared device risk, data quality checks). Rule simulation runs in Python, without Spark ([ADR-05](./decisions.mdx#adr-05)). |
| **Step Functions** | Orchestrates the nightly run: read statements, reconcile with Spark, save differences, then the analytics (export, Spark ETL, Athena views), with retries per step. |
| **EventBridge Scheduler** | Starts every scheduled process: reconciliation at 02:00, daily loads and ETL, alerts every 5 minutes and the weekly jobs. |

### Analytics

| Service | Role in PagoSeguro |
| :--- | :--- |
| **Glue Data Catalog** | Keeps the table definitions of the Data Lake. |
| **Athena** | SQL straight on S3, without moving data or keeping a cluster running. |
| **Power BI** | The dashboard, connected to Athena through the Athena ODBC driver ([Power BI over Athena](../getting-started/deploy-aws-terraform.mdx#power-bi-over-athena)). |

### Operations

| Service | Role in PagoSeguro |
| :--- | :--- |
| **CloudWatch** | Logs, metrics and the [alarms](./infrastructure.mdx#alarms). |
| **X-Ray** | Not built ([team decision](./team-decisions.mdx#x-ray-is-left-out)): the engine's decision log and CloudWatch cover it. |
| **Systems Manager** | Parameter Store keeps the database passwords; Session Manager gives the team access to the private network. |
| **ECR** | Registry of the container images. |
| **Terraform and GitHub Actions** | Create the whole infrastructure and deploy each new version after the tests pass. |

## Where the data comes from {/* #data-sources */}

<Callout title="Synthetic data only" type="note">
Nothing comes from a real system:
</Callout>

| Source | What it is | Status |
| :--- | :--- | :--- |
| [Seed](../components/seed.mdx) | Users, accounts, devices, merchants and restricted lists in PostgreSQL. | Done |
| [Transaction generator](../components/generator.mdx) | Plays the wallet core: transaction stream with fraud patterns and defects. | Done |
| [Kaggle datasets](../components/kaggle-datasets.mdx) | PaySim (transfers) and Sparkov (card payments): labeled history for rule effectiveness, never sent through the engine (see [Team decisions](./team-decisions.mdx#card-payment-history-sparkov)). | Done (local and LocalStack) |
| [Partner statements](../components/partner-statements.mdx) | Daily files from four payment partners, for reconciliation, built from the generator's output with the assignment's defects. | Done (local and LocalStack) |
| [Exchange rates](../components/exchange_rates.mdx) | Frankfurter public API (v2), loaded once a day into DynamoDB. | Done (local and LocalStack) |
| Restricted list service | A simulated provider that is slow and fails on purpose. It serves the list the seed exports to S3; the engine never calls it, it reads the cached copy of the seed's table (see [Restricted list service](../components/restricted-list.mdx)). | Done (local and LocalStack) |
