# Terraform

The design in [AWS infrastructure](./infrastructure.mdx) and [Security](./security.mdx) is written as Terraform code in `infra/terraform/`. This page explains how that code is organized and how to create and destroy an environment. The code implements the design and does not change it; the only deliberate differences are the English names (next section) and the development settings that keep a test cheap and easy to destroy.

**Status.** Network, security groups, IAM, S3 and RDS exist in code. They pass `terraform fmt -check` and `terraform validate`, and a full `apply` and `destroy` against a simulated AWS ([moto](https://github.com/getmoto/moto)). On 2026-10-23 they were created in the team's AWS account (139 resources), checked (`terraform plan` said `No changes` and the evidence bucket refused to delete a locked object) and destroyed (`terraform state list` empty). The services that come in later sprints (load balancer, ECS, Lambdas, cache, queues) are not in the code yet.

## Names in AWS

Every resource is named `securepay-<environment>-<resource>` and is in English, like the repositories. The design pages still use the earlier Spanish names; this is how they map:

| Design name | Name in AWS (dev) |
| :--- | :--- |
| `pagoseguro-prod-vpc` | `securepay-dev-vpc` |
| `publica-a/b`, `app-a/b`, `datos-a/b` | `securepay-dev-public-a/b`, `securepay-dev-app-a/b`, `securepay-dev-data-a/b` |
| `sg-alb`, `sg-motor`, `sg-lambda`, `sg-admin`, `sg-rds`, `sg-cache` | `securepay-dev-sg-alb`, `-sg-engine`, `-sg-lambda`, `-sg-admin`, `-sg-rds`, `-sg-cache` |
| `rol-motor`, `rol-consumidor-casos`, ... | `securepay-dev-engine`, `securepay-dev-cases-consumer`, ... (one per component, see the IAM table below) |
| `pagoseguro-prod-datalake`, `-evidencia`, `-proveedor-listas`, `-artefactos` | `securepay-dev-datalake-<account>`, `-evidence-<account>`, `-list-provider-<account>`, `-artifacts-<account>` |
| `pagoseguro-prod-db` | `securepay-dev-db` |
| `/pagoseguro/prod/rds/...` | `/securepay/dev/rds/...` |

Bucket names end with the AWS account number because S3 names are global: `securepay-dev-datalake` alone could already belong to someone else. The data paths inside the buckets (`raw/decisiones/`, `raw/extractos/`, `curated/conciliacion/`) stay as the code writes them today.

**Tags.** Every resource carries `project`, `environment`, `owner` and `managed_by`, through the provider's `default_tags`. They are the project, environment and owner tags the assignment asks for (CT-03), in English.

## Structure

```
infra/terraform/
├── terraform-user-policy.json  IAM permissions the person running Terraform needs (besides PowerUserAccess)
├── modules/
│   ├── network/            VPC, 6 subnets, Internet Gateway, 2 NAT Gateways, route tables, S3 and DynamoDB endpoints
│   ├── security_groups/    the 6 security groups and their rules
│   ├── iam/                one role per component, the GitHub deploy role and the Power BI user
│   ├── storage/            the 4 S3 buckets
│   ├── database/           RDS PostgreSQL and its passwords in Parameter Store
│   ├── ecr/                one image repository per component
│   ├── cache/              ElastiCache Serverless for Valkey
│   └── ecs/                cluster, load balancer, engine service with autoscaling, admin task
└── envs/
    └── dev/                the development environment: uses the modules, budget alert
        ├── main.tf
        ├── variables.tf
        ├── outputs.tf
        ├── versions.tf     Terraform >= 1.9, AWS provider 5.80.0, random 3.6.3 and tls 4.0.6, fixed
        ├── .terraform.lock.hcl
        └── terraform.tfvars.example
```

A module is the reusable piece. An environment folder chooses its values and calls the modules. Only `dev` exists so far.

| What | How |
| :--- | :--- |
| Region and zones | `us-east-2` by default; the zones are the first two that `aws_availability_zones` returns |
| State | Local (`terraform.tfstate`), ignored by git. Always run `apply` and `destroy` from the same computer: another computer has no state and does not know what exists |
| Credentials | Never in files. Terraform takes them from your AWS profile (`aws configure`) |
| Secrets | The RDS passwords are generated by Terraform and stored as `SecureString` parameters. They are also in `terraform.tfstate` in plain text, another reason the state is never committed or shared |
| Variable values | `terraform.tfvars`, ignored by git; `terraform.tfvars.example` shows what to fill in |

## What it creates

The first `plan` must say `159 to add, 0 to change, 0 to destroy`. Once the image tags are set (see [Deploy the engine](../getting-started/deploy-aws-terraform.mdx#6-deploy-the-engine-on-fargate)), the next one adds 5 more: the two task definitions, the engine service and its autoscaling target and policy.

| :--- | :--- | :--- |
| `network` | 1 VPC | `10.0.0.0/16`, DNS enabled |
| | 6 subnets | `public-a/b` (10.0.0.0/24, 10.0.1.0/24), `app-a/b` (10.0.10.0/24, 10.0.11.0/24), `data-a/b` (10.0.20.0/24, 10.0.21.0/24) |

| | 4 route tables | Public to the Internet Gateway; each application table to the NAT in its own zone; data with no default route |
| | 2 gateway endpoints | S3 and DynamoDB, on the two application tables and the data table |
| `security_groups` | 6 groups and their rules | Exactly the ports in [Security groups](./security.mdx#security-groups). The rules point at other groups, not at address ranges. `sg-rds` and `sg-cache` have no outbound rule, so no outbound access |
| `iam` | 21 roles, GitHub OIDC provider, Power BI user | The permissions of [Identity and access](./security.mdx#iam). The roles are scoped to the ARNs of resources that later sprints create, built from the naming convention, so they do not depend on those resources existing |
| `storage` | 4 buckets | Versioning, S3 managed encryption, public access blocked, requests without TLS denied. Object Lock on the evidence bucket |
| `database` | RDS, subnet group, parameter group, 7 passwords | PostgreSQL 16, `db.t3.micro`, Multi-AZ, 20 GB gp3, encrypted, `rds.force_ssl = 1`, automated backups, not public. The master password and the 6 component passwords go to `/securepay/dev/rds/` |
| `ecr` | 3 repositories and their lifecycle rules | `securepay-dev-engine`, `-generator`, `-admin`. Scan on push, immutable tags (an image is tagged with the short git commit, never only `latest`), keeps the last 10 images |
| `cache` | 1 serverless cache | `securepay-dev-cache`, Valkey 8, in the data subnets with `sg-cache`, encryption in transit always on (`rediss://`), limits of 1 GB and 5,000 ECPU/s. Clients must speak the cluster protocol, so the engine runs with `VALKEY_CLUSTER=true` |
| `ecs` | Cluster, 2 log groups, load balancer, target group, HTTPS listener, certificate | Cluster `securepay-dev` (Fargate only). Load balancer `securepay-dev-alb` in the public subnets, listener on 443 with TLS 1.2 or 1.3, target group to port 8000 with a health check on `GET /health` |
| | Engine service (once `engine_image_tag` is set) | Service `engine`, 0.5 vCPU / 1 GB per task in `app-a` and `app-b`, no public address, deployment circuit breaker with rollback, CPU target tracking at 60 % |
| | Admin task (once `admin_image_tag` is set) | Task definition `securepay-dev-admin` with the `securepay-seed` image, 0.25 vCPU / 0.5 GB. It runs only when started with `aws ecs run-task` |
| `envs/dev` | 1 budget | See below |

**The 21 roles.** `engine-execution`, `engine`, `cases-consumer`, `history-consumer`, `analytics-consumer`, `firehose-raw`, `rules-api`, `cases-api`, `rules-cache-refresh`, `alerts`, `exchange-rates`, `list-loader`, `list-service`, `statement-reader`, `difference-writer`, `reconciliation`, `emr-jobs`, `scheduler`, `admin-execution`, `admin` and `deploy`, each `securepay-dev-<name>`. The deploy role only trusts GitHub tokens from the `main` branch of `SecurePay-Riwi/SecurePay`. The EMR Serverless application id does not exist yet, so the roles that start Spark jobs are scoped to the applications of the account until it does.

**Engine port.** [Security](./security.mdx#security-groups) says 8080, and the current engine image listens on 8000. The port is the variable `engine_port`, 8000 by default, until the team decides which one stays.

### What is different in dev, and why

| Setting | Prod (design) | Dev | Why |
| :--- | :--- | :--- | :--- |
| Evidence retention | Object Lock COMPLIANCE, 10 years by default | No default retention; the test object is uploaded with its own retain-until date 5 minutes ahead | Not Terraform: the lock is set by the upload command. AWS does not accept less than 1 day of default retention, and a locked object stops `destroy`. For those 5 minutes nobody can delete the object, not even the root account; after that the bucket is destroyed normally. If this is not accepted, the alternative is the 1-day default and destroying the bucket the next day |
| Buckets with objects | Not deleted | `force_destroy = true` | `destroy` empties them first |
| RDS | Deletion protection and a final snapshot | Neither | `destroy` deletes it at once and leaves no snapshot that keeps costing |
| RDS backups | 7 days | 1 day (`database_backup_retention_days`) | An AWS account on the free plan rejects more than 1 day (`FreeTierRestrictionError`) |
| Engine tasks | 4 to 24 | 2 to 4 (`engine_min_tasks`, `engine_max_tasks`) | One per zone is enough to show the failover; the load test sizes prod |
| Load balancer certificate | ACM certificate for the domain | Self-signed, generated by Terraform and imported into ACM (`curl -k`) | There is no domain yet. Setting `domain_name` switches to a public ACM certificate validated by DNS; the record to add is the output `certificate_validation_records` |
| Engine to database | No access | 5432 open from `sg-engine` to `sg-rds` and `DATABASE_URL` from Parameter Store (`engine_reads_database = true`) | Temporary: the engine code still reads accounts, merchants, owners and the restricted list from PostgreSQL (see [Security](./security.mdx#security-groups)) |
| Container Insights, logs | On, 30 days | Off, 7 days | Container Insights bills extra metrics |
| Image repositories with images | Not deleted | `force_delete = true` | `destroy` deletes the images too |
| Budget | 80 % and 100 % of the USD 200 credit | USD 5 a month, an email at every 10 % | Dev only lives during a test |

**Budget.** It measures usage before credits are subtracted (`include_credit = false`). Credits appear on the bill as a negative amount, so a budget that includes them sees USD 0 while the credit lasts and never alerts. AWS refreshes costs about three times a day, so an email can arrive hours after the spend: the real protection is destroying the environment right after each test. Budget alerts are free.

## Outputs

| Output | Content |
| :--- | :--- |
| `vpc_id` | The VPC |
| `public_subnet_ids`, `app_subnet_ids`, `data_subnet_ids` | Two subnet ids each, zone a first |
| `nat_public_ips` | The addresses the private subnets go out with |
| `security_group_ids` | Group id by function: `alb`, `engine`, `lambda`, `admin`, `rds`, `cache` |
| `role_arns` | Role ARN by component |
| `bucket_names` | Bucket name by purpose: `datalake`, `evidence`, `list-provider`, `artifacts` |
| `database_endpoint` | RDS host name, reachable only inside the VPC |
| `database_master_password_parameter` | Parameter Store name of the master password; the password itself is never an output |
| `ecr_repository_urls` | Where to push each image: `<url>:<short commit>` |
| `alb_dns_name` | Public name of the load balancer |
| `ecs_cluster_name` | `securepay-dev` |
| `cache_address` | Cache host name, reachable only inside the VPC |
| `admin_run_task_command` | The command that seeds the database with the admin task |
| `certificate_validation_records` | With `domain_name`: the DNS record ACM needs; empty otherwise |

## Create and destroy the development environment

[Deploy to AWS with Terraform](../getting-started/deploy-aws-terraform.mdx) has every step: installing the AWS CLI and Terraform, the IAM user and its access key, creating, checking, the Object Lock test and destroying. In short, from `infra/terraform/envs/dev`:

```bash
cp terraform.tfvars.example terraform.tfvars   # your name and email
terraform init
terraform plan       # the first time: 159 to add
terraform apply
terraform destroy    # always when you finish testing
```

**Recreate.** After a `destroy`, `terraform apply` creates the same resources with the same names and ranges (only the ids and the NAT public addresses change). Right after an `apply`, `terraform plan` must say `No changes`.

**Before every pull request:** `terraform fmt -check -recursive` in `infra/terraform/` and `terraform validate` in `envs/dev`.
