# Architecture summary

**Event-driven microservices, managed services first**, in AWS Ohio (`us-east-2`) across two Availability Zones. The core idea is to split the system into two paths.

<div className="path-grid">
  <InfoCard title="Fast path · the decision">
    The core sends the transaction over HTTPS to a load balancer, which spreads it across the decision engine tasks. The engine reads and updates everything it needs in an in-memory cache: idempotency, time windows, 24-hour sums, active rules and the full restricted list. With that it answers. It never queries a database or waits for another process. If it runs late, it decides by amount: it approves under USD 50 and holds from USD 50 up.
  </InfoCard>
  <InfoCard title="Slow path · everything else">
    After answering, the engine publishes the decision to a messaging topic that copies it to three independent queues:
    <ul>
      <li><strong>Cases:</strong> opens a case for the analysts only when mule account, transaction splitting or restricted list fired.</li>
      <li><strong>History:</strong> keeps which devices each account used in the last 30 days.</li>
      <li><strong>Analytics:</strong> takes the decision to the Data Lake.</li>
    </ul>
    If one queue falls behind, the others keep going.
  </InfoCard>
  <InfoCard title="Scheduled processes">
    Every night the statements of the four payment partners are reconciled. Every day the exchange rates and the restricted list are loaded. Every five minutes a task escalates overdue cases, notifies compliance and reviews the approvals made by the fallback policy. Spark processes the Data Lake, measures rule effectiveness on the labeled history and simulates a new rule before it is activated. Power BI shows the dashboard.
  </InfoCard>
</div>

## The services we use {/* #services */}

The general rule: **pay for capacity where volume is high and pay per use where it is low**, and always prefer a service AWS runs for us, because the team has six weeks and the time must go to the business rules. Each service, its purpose and why it was chosen are in [AWS infrastructure](./infrastructure.mdx#services); the highest-impact choices are recorded as [architecture decisions](./decisions.mdx).

## How the design meets the requirements {/* #requirements */}

| Requirement | How it is met |
| :--- | :--- |
| **Decision in under 200 ms** at 300 tx/s | Everything the engine reads is in memory; nothing slow on the path. Its own time is estimated at 9 to 22 ms, and it cuts off at 120 ms with the amount-based policy |
| **Keep running if a zone goes down** | Two zones for everything with state: engine, database with a standby replica, replicated cache, one NAT per zone. The 24-task maximum leaves 12 alive, enough for the peak |
| **A repeated transaction gets the same decision** | Idempotency key in the cache for one hour (already built) |
| **Change rules without deploying** | Rules are versioned data in PostgreSQL; activating a version sends an event that refreshes the cache at once |
| **Security** | Everything in private subnets except the load balancer; encryption in transit and at rest; one least-privilege role per component; passwords in Parameter Store, never in code; no exposed access servers |
| **Immutable evidence for 10 years** | S3 Object Lock in COMPLIANCE mode, written by the cases API when each case closes |
| **Reconciliation before 07:00** | Starts at 02:00, with retries per step and an alarm at 06:30 |
| **Suspicious-operations report** | Recorded immediately at decision time, summary to compliance every 5 minutes |
| **Simulate a rule without touching production** | Spark evaluates the candidate rule on the labeled history, with the same interpreter as the engine, on separate compute |

Network, security groups and IAM roles are in [Security](./security.mdx); the full resource list in [AWS infrastructure](./infrastructure.mdx).

## What the solution costs {/* #cost */}

**Production: ≈ $333 a month. Development: ≈ $17 a month**, because the development environment is destroyed between work sessions. Figures use AWS published prices for Ohio and a load of 50 tx/s sustained (129.6 million transactions a month).

**Why this is the lowest-cost option:**

| Alternative | Monthly cost | Why not |
| :--- | :--- | :--- |
| **Our design** | **≈ $333** | |
| Everything on Fargate containers | ≈ $401 | Pays for idle containers for the low-volume components |
| The assignment's stack: RabbitMQ, Airflow, own Spark, EKS | ≈ $320 without high availability | Adding broker and Airflow replicas to survive a zone outage makes it more expensive, and the team would run four systems |

Some figures, such as requests per task, cache memory and Spark job duration, are confirmed by the load test and the first real runs; they are parameters adjusted without changing services or flow. Full breakdown in [AWS services and costs](./aws-services-and-costs.mdx), and how each estimate was calculated in [AWS infrastructure](./infrastructure.mdx#estimates).
