## Repository layout

The project is split into five repositories under the SecurePay-Riwi organization, cloned side by side in the same folder:

| Repository | What it has |
|---|---|
| [`SecurePay`](https://github.com/SecurePay-Riwi/SecurePay) | The product: decision engine, consumers, local infrastructure, this site |
| [`securepay-seed`](https://github.com/SecurePay-Riwi/securepay-seed) | PostgreSQL seed and Kaggle ETL |
| [`securepay-generator`](https://github.com/SecurePay-Riwi/securepay-generator) | Transaction generator (simulated core) |
| [`securepay-csv`](https://github.com/SecurePay-Riwi/securepay-csv) | Kaggle datasets and partner statements |
| [`securepay-apis`](https://github.com/SecurePay-Riwi/securepay-apis) | Restricted list service and exchange rates |

The source repositories never import each other: they exchange files (and S3 in AWS). Each one has a single package under `src/`, tests under `tests/`, and an `AGENTS.md` with its structure rules. Shared models and config come from the [`securepay-shared`](https://pypi.org/project/securepay-shared/) package.

```text
SecurePay/
├── services/
│   ├── decision_engine/   # decision engine (FastAPI) and its tests
│   └── consumers/         # SQS consumers with the Lambda signature, and their tests
├── shared/                # SQLAlchemy models, DB/Valkey/AWS clients, decision event format
├── infra/localstack/init/ # creates SNS, SQS, S3 and DynamoDB in LocalStack
├── doc-website/           # this documentation site (Docusaurus)
├── docker-compose.yml     # PostgreSQL, Valkey and LocalStack for local development
├── pyproject.toml         # dependencies and pytest config (uv)
├── uv.lock
└── db/, generators/, sources/   # backup from before the split; do not edit
```

Coming later: `services/rules_api/` (the rules API, HU-19), `services/scheduled/`, `jobs/` (PySpark) and Terraform under `infra/`. Shared code that the engine and Spark must run identically, like the **rule interpreter**, goes in `shared/`.

Folders use underscores (`decision_engine`, not `decision-engine`) because Python cannot import modules with hyphens.

These conventions apply to every repository of the SecurePay-Riwi organization; they are also in each repository's `AGENTS.md` (PR #48).

## Branches

`type/TICKET-short-description`, lowercase with hyphens. The ticket is the Jira key.

| Branch | Use |
| :--- | :--- |
| `main` | Always working. Only changes through pull requests. |
| `feature/MAG-123-short-name` | New work, e.g. `feature/MAG-129-shared-device`. |
| `bugfix/MAG-123-short-name` | A fix that is not urgent. |
| `hotfix/MAG-123-short-name` | Urgent fixes to `main`. |
| `refactor/MAG-123-short-name` | Restructuring without behavior changes. |
| `test/MAG-123-short-name` | Tests only. |
| `doc/MAG-123-short-name` | Documentation only. |

Branches that already exist keep their names. There is no `develop` branch: branches merge straight into `main` through pull requests.

## Commits

- In **English**, in the [Conventional Commits](https://www.conventionalcommits.org/) style: `type(scope): description`. Types: `feat`, `fix`, `perf`, `build`, `ci`, `docs`, `refactor`, `style`, `test`, `chore`. The scope is the component or the Jira key: `feat(MAG-31): …`, `fix(seed): …`.
- Imperative mood ("add", not "added"), no final period, a title of 50 characters or less; extra context goes in the body. Reference issues with `closes #12`.
- No `Co-Authored-By` lines.
- One logical change per commit. Commits made before October 13, 2026 are in Spanish and stay that way.
- Never commit `.env`, tokens or passwords. `.env.example` lists every variable with safe defaults.

## Pull requests

1. Branch from an up-to-date `main`.
2. Run `uv run pytest` with PostgreSQL (seeded), Valkey and LocalStack up.
3. Update the repository `README.md`, these docs and `AGENTS.md` when you add setup steps, environment variables or ways to run something.
4. Keep it small: ideally under 10 files and a few hundred lines. Open it as **Draft** while it is in progress, with a title in the commit format.
5. The description follows the organization template ([`pull_request_template.md`](https://github.com/SecurePay-Riwi/.github/blob/main/pull_request_template.md)): Context (with the Jira key), Type of change, Before / After, How and why, Missing, How to test (exact commands, where they run and the expected result) and Checklist.
6. At least one other team member reviews before merging. Prefer **Squash and merge**, and delete the branch after the merge.

## Continuous integration

`.github/workflows/docker-validation.yml` runs on every pull request to `main` that touches the `Dockerfile`, `docker-compose.yml`, `.dockerignore`, a `pyproject.toml` or `uv.lock`, `README.md`, `AGENTS.md` or the local setup page, and on pushes to `main` that touch the Docker files or dependencies. It checks out this repository and the four source repositories side by side, validates the Compose file, builds every image and starts the whole environment, checking the health endpoints. The test suite does not run in CI yet (EP-12).

## Documentation site

The site lives in `doc-website/` and is deployed to GitHub Pages by `.github/workflows/doc-site.yml` on every push to `main` that touches it. To preview locally:

```bash
cd doc-website
npm ci
npm run start
```

`onBrokenLinks: 'throw'` makes the build fail on a broken internal link, so run `npm run build` before opening a PR. How the site was set up: [How the documentation site was built](./how-was-created-this-docu.mdx).
