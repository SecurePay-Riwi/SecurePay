## Sprint result

Sprint 3 was closed on October 24, 2026 with nine of ten stories done. HU-15 (splitting) has its rule merged, but its criterion "a compliance case is created" needs the cases consumer, so the story moved to Sprint 4 and closes together with HU-25. The engine now runs seven rules from a versioned catalog (restricted list, velocity, mule account, shared device, splitting, account takeover and the default decision on timeout). The rules API changes, enables, disables and versions them in PostgreSQL, the engine picks up the new catalog from Valkey without a restart, and every decision records the version of each rule that decided it. The AWS network, IAM, security groups, S3 and RDS are written in Terraform; they were created in the team's AWS account on October 23, checked and destroyed, and the cost analysis v1 is on the [AWS services and costs](../architecture/aws-services-and-costs.mdx) page.

## How the work is split

The sprint is split **by module**, so each person works on their own part of the code and nobody waits for or collides with another person in the same files:

- **Yulianis** takes the whole rule catalog, in order: HU-19 → HU-20 → HU-21 → HU-22. One line of work in one module.
- **Jorge** takes AWS (HU-55 → HU-56), where he is strongest, and account takeover (HU-17), which he can interleave.
- **Habith**, as Scrum Master, keeps the lightest load because he reviews and integrates: first a refactor ("step 0", PR #49) that puts the shared shape of the catalog in the code, then HU-14 → HU-15, and HU-23 at the end.

## Dependencies and waits

- HU-20, HU-21 and HU-22 depend on HU-19; HU-23 depends on HU-22; HU-56 depends on HU-55 (see [Dependencies](./hu-dependencies.mdx)).
- Step 0 had to land before any work on rules. It is in `main` since October 22, so nobody waits for it anymore.
- The only wait between people is **HU-23 (Habith) after HU-22 (Yulianis)**, so HU-23 goes last.
- At the end of the sprint every rule, old and new, is managed through the catalog: a threshold changed through the API is used by the next decision, which records the new version, without restarting the engine (CA-06).
