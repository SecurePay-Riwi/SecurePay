# Kaggle Datasets

## Overview

The Kaggle integration provides historical labeled fraud data for two independent
purposes: loading a reproducible transaction sample into **PostgreSQL** for local
antifraud development, and ingesting raw datasets into the **Data Lake** (S3/LocalStack)
for downstream analytics.

- **Datasets used:** PaySim, Fraud Detection, Credit Card Fraud
- **Source:** [Kaggle](https://www.kaggle.com)
- **Authentication:** Kaggle API token (only needed for automatic download)
- **Update frequency:** Static — datasets are fixed historical snapshots
- **CSV files:** Not committed to Git due to file size

:::note
The two workflows are independent. `fraudTest.csv` is used only by the PostgreSQL ETL.
`creditcard.csv` is used only by the Data Lake loader. Do not substitute one for the other —
they have different schemas.
:::

## Where it lives

```text
sources/
└── csv_files/
    └── kaggle/              ← Data Lake loader entry point

db/
└── datasets/                ← PostgreSQL ETL

data/
├── raw/                     ← ETL input (fraudTest.csv + PaySim)
└── kaggle/                  ← Data Lake input (creditcard.csv + PaySim)
```

The `data/` directories are local and must remain ignored by Git.
Do not commit the CSVs, `.env`, or `.venv`.

## How it works

### PostgreSQL ETL (local development)

The ETL in `db/datasets/` loads a controlled sample from PaySim and `fraudTest.csv`
into the existing `transacciones` table. It depends on seed data — transactions are
assigned to users, devices, and merchants created by the seed.

```text
data/raw/ (PaySim + fraudTest.csv)
    ↓
db/datasets/etl.py
    ↓
PostgreSQL → transacciones table
```

The default sample uses **50,000 PaySim rows** and **20,000 fraudTest rows**,
each with a configured 3% fraud share. Transaction IDs are deterministic,
so reruns do not insert duplicates.

### Data Lake ingestion (S3 / LocalStack)

The module `sources/csv_files/kaggle/` validates and uploads PaySim and
Credit Card Fraud to the raw layer of the Data Lake. It does not transform
the files or load them into PostgreSQL.

```text
data/kaggle/ (PaySim + creditcard.csv)
    ↓
sources/csv_files/kaggle/
    ↓
S3 / LocalStack → pagoseguro-datalake/raw/kaggle/
```

For each dataset the loader checks the file exists, validates the exact header
and expected row count, calculates SHA-256, uploads the CSV, and writes a manifest
only after a successful upload.

## Key decisions

:::info Design decisions
- **Two separate input directories:** `data/raw/` for ETL and `data/kaggle/` for the
  Data Lake loader. This avoids accidental cross-contamination between workflows.
- **Strict header and row-count validation:** if a file does not match its expected
  contract it is not uploaded. The contract is never relaxed just to pass a different file version.
- **Deterministic transaction IDs in the ETL:** reruns are safe and do not create
  duplicate rows in `transacciones`.
- **Manifests written only after successful upload:** partial uploads leave no manifest,
  making it easy to detect incomplete state.
- **PaySim used by both workflows independently:** each workflow reads it from its own
  configured local directory.
:::

## How to run it locally

### 1. PostgreSQL ETL

Make sure the database is running and the seed has been executed first.
Place the two required CSVs in `data/raw/`, then run a dry-run to preview:

```bash
uv run python -m db.datasets.etl --dry-run
```

If the preview looks correct, run the ETL:

```bash
uv run python -m db.datasets.etl
```

Expected output:

```text
Loading PaySim sample: 50000 rows (3% fraud)
Loading fraudTest sample: 20000 rows (3% fraud)
Batch fingerprint (SHA-256): abc123...
ETL complete.
```

### 2. Data Lake ingestion

Start the local dependencies:

```bash
docker compose up -d valkey localstack
docker compose ps
```

Then run the loader:

```bash
uv run python -m sources.csv_files.kaggle
```

Expected output:

```text
[paysim] Validating... OK (6362620 rows)
[paysim] Uploading to s3://pagoseguro-datalake/raw/kaggle/paysim/paysim.csv ... OK
[paysim] Manifest written.
[creditcard] Validating... OK (284807 rows)
[creditcard] Uploading to s3://pagoseguro-datalake/raw/kaggle/creditcard/creditcard.csv ... OK
[creditcard] Manifest written.
```

### 3. Verify the upload

```bash
uv run python -c "from shared.aws import cliente; [print(o['Key'], o['Size']) for o in cliente('s3').list_objects_v2(Bucket='pagoseguro-datalake', Prefix='raw/kaggle/')['Contents']]"
```

You should see the two CSV objects and their two manifests.

## Tests

The tests do not download real datasets or write to the database.
The S3 integration test is skipped when LocalStack is unavailable.

```bash
# ETL tests
uv run pytest db/datasets

# Data Lake loader tests
uv run pytest sources/csv_files/kaggle
```

## Error handling

If a dataset fails validation or upload:

- No partial data is written — the manifest is only created after a successful upload.
- Processing of the other dataset is still attempted.
- In the ETL, a failed run leaves `transacciones` unchanged if it errors before commit.

## ETL configuration

| **Variable** | **Default** | **Purpose** |
| :--- | ---: | :--- |
| `HIST_PAYSIM_FILAS` | `50000` | Number of PaySim rows selected |
| `HIST_PAYSIM_FRAUDE_PCT` | `3` | Fraud percentage in the PaySim sample |
| `HIST_FRAUDTEST_FILAS` | `20000` | Number of `fraudTest` rows selected |
| `HIST_FRAUDTEST_FRAUDE_PCT` | `3` | Fraud percentage in the `fraudTest` sample |
| `HIST_RAW_DIR` | `data/raw` | Directory containing the ETL CSVs |
| `KAGGLE_API_TOKEN` | — | Required only for automatic download |
| `KAGGLE_DOWNLOAD_DIR` | `data/kaggle` | Local directory for Data Lake CSVs |
| `DATALAKE_BUCKET` | `pagoseguro-datalake` | S3 bucket name |

## Troubleshooting

| **Symptom** | **Possible cause / action** |
| :--- | :--- |
| `Falta KAGGLE_API_TOKEN en el .env` | Token missing and CSV not in `data/kaggle/`. Add the token or place the file manually. |
| Header or row count does not match | Wrong file version. Check filename and source; do not change the validation contract. |
| `NoSuchBucket` or connection error | Start LocalStack and verify the `pagoseguro-datalake` bucket was initialized. |
| ETL cannot find a CSV | Confirm files are in `data/raw/` and `HIST_RAW_DIR` points there. |
| Different ETL fingerprint | Check CSV hashes, seed/config values, `HIST_*` settings, and locked dependencies. |
