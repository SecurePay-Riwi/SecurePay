# Testing

Each repository runs its own tests with `uv run pytest` from its root:

| Repository | Tests | Where | Needs |
| :--- | ---: | :--- | :--- |
| `SecurePay` | 419 (engine, rules API, cases API, alerts, consumers, shared, end to end) | `services/*/tests/`, `shared/tests/`, `tests/` | PostgreSQL with the seed, Valkey, LocalStack |
| `securepay-seed` | 29 | `tests/seed/`, `tests/kaggle_etl/` | Nothing |
| `securepay-generator` | 32 | `tests/` | Nothing |
| `securepay-csv` | 46 | `tests/kaggle_datasets/`, `tests/partner_statements/` | Nothing (one test uses LocalStack and is skipped without it) |
| `securepay-apis` | 38 | `tests/restricted_list/`, `tests/exchange_rates/` | Nothing (two tests use LocalStack and are skipped without it) |

## How to run the tests

**1. Start the local services**, so that no test is skipped (see [Local setup](./local-setup.mdx)):

```bash
docker compose up -d
```

**2. Load the seed** from the `securepay-seed` repository. The engine API tests need the users, accounts and restricted list in PostgreSQL:

```bash
cd ../securepay-seed
uv run python -m securepay_seed.seed
```

**3. Run the tests from the root of each repository:**

```bash
uv run pytest
```

**Run only part of the suite:**

```bash
uv run pytest services/decision_engine   # SecurePay: only the engine
uv run pytest services/consumers         # SecurePay: only the consumers and messaging
uv run pytest shared                     # SecurePay: only shared/ (database connection, case tables)
uv run pytest tests/partner_statements   # securepay-csv: only the partner statements
uv run pytest -k velocity                # tests whose name contains "velocity"
uv run pytest -rs                        # also show why each test was skipped
uv run pytest -x                         # stop at the first failure
```

## API contract and Bruno collection (E-05) {/* #api-contract */}

The contract of the three HTTP services is exported to `doc-website/static/openapi/` (`decision-engine.json`, `rules-api.json`, `cases-api.json`), the same document each service serves at `/openapi.json`. The site publishes them, so they can be read without starting anything. After changing an endpoint, a status code or a schema, export them again and commit them; `tests/test_openapi_export.py` fails until you do:

```bash
uv run python -m infra.api.openapi
```

`infra/api/bruno/` is a [Bruno](https://www.usebruno.com/) collection with 41 requests against the local stack: the happy path and the documented errors of every endpoint (decision engine 7, rules API 14, cases API 20). Each request checks its status code. It needs the Compose stack up and seeded ([Local setup](./local-setup.mdx)); nothing in AWS:

```bash
docker compose up -d
npm install -g @usebruno/cli
cd infra/api/bruno
bru run --env local
```

Expected: every request passes. Request 03 of the engine reuses the id of request 02, so run the engine's folder in order (`bru run` does). The rules requests never change the catalog: the ones that would are refused (409, 404 or 400) before anything is stored, enabling `velocity` finds it already enabled, and `POST /rules/publish` only writes the latest version to Valkey again. The happy request of `GET /cases/{case_id}/senders` (cases 20) uses the first pending case of request 02 and is skipped while the stack has no case yet. In the Bruno app, open the folder `infra/api/bruno` as a collection and pick the `local` environment.

## How to read the results

pytest prints one character per test while it runs and a summary line at the end:

| Mark | Meaning | What to do |
| :--- | :--- | :--- |
| `.` | Passed | Nothing. |
| `s` | Skipped: a service it needs (Valkey or LocalStack) is off | Start it with `docker compose up -d` and run again. `-rs` says which service. |
| `F` | Failed: the code did not do what the test expects | Read the assertion under `FAILURES`; it shows the expected and the actual value. |
| `E` | Error while preparing the test (a fixture failed) | Usually configuration: a wrong `.env` value or a missing seed. |

**A healthy run** with every service up and the seed loaded ends with all tests passed:

```text
181 passed
```

**The same run with nothing started** (no Docker) looks like this. It is expected, not a bug:

```text
14 failed, 148 passed, 19 skipped in 16.17s
```

- The **19 skipped** are the Valkey and LocalStack tests: they detect the service is off and skip themselves.
- The **14 failed** are the engine API tests. They do not skip: the engine answers `503` when Valkey is down, so they fail on purpose to make the missing dependency visible.

**Common causes of a failure:**

| Symptom | Likely cause |
| :--- | :--- |
| API tests fail with `503` | Valkey is not running. |
| API tests fail with `422` (account not found) | The seed is not loaded, or it was loaded with another seed value. Reload it with `SEED_RESET=true`. |
| Velocity or idempotency results look shifted | Keys left over from a previous run. Clean Valkey (see [Simulate the full flow](./simulate-full-flow.mdx#1-clean-valkey)). |
| A "PostgreSQL down" test hangs on Windows | Port 1 does not refuse at once on Windows. Those tests use `shared/tests/isolated_db.down_sessions()`, which sets `connect_timeout`; a new test of that kind must use it too. |
| A generator test with exact counts fails | Something changed the generator's randomness; with seed 42 it must always produce 1,035 events. |
| Tests touch a database you did not expect | They use `DATABASE_URL` from `.env`, not the stack's PostgreSQL: 5432 is an installed one, 5433 the Compose one. |

## In CI

Every pull request to `main` runs the same checks in GitHub Actions (`.github/workflows/ci.yml`): `lint`, `secret-scan`, `tests`, `image` and `terraform`. To run them on your machine before opening the PR, from the root of `SecurePay`:

```bash
uv run ruff format --check .                          # format (ruff format . fixes it)
uv run ruff check .                                   # lint
docker run --rm -v "$PWD:/repo" zricethezav/gitleaks:v8.28.0 git /repo --log-opts="HEAD" --redact   # secret scan
uv run pytest                                          # tests (steps 1 and 2 above first)
docker build --provenance=false -t securepay-engine:ci .                         # image
(cd infra/terraform && terraform fmt -check -recursive && cd envs/dev && terraform init -backend=false && terraform validate)   # terraform
```

`ruff check --fix` fixes what it can by itself. The commit that formatted the whole repository is in `.git-blame-ignore-revs`; run `git config blame.ignoreRevsFile .git-blame-ignore-revs` once so `git blame` skips it. If gitleaks flags a real key, rotate it first (it is already in the history); only then add the fingerprint it prints to `.gitleaksignore`. The CI test job has no LocalStack, so the tests that need it are skipped there; run them locally with `docker compose up -d`.

The source repositories (`securepay-seed`, `securepay-generator`, `securepay-csv`, `securepay-apis`) run `lint`, `secret-scan` and `tests` on every pull request too. From the root of each one: `uv run ruff format .`, `uv run ruff check .` and `uv run pytest` ([Contributing](../contributing.mdx#ci-of-the-source-repositories)).

## Conventions

- Each rule's fraud pattern has a **control case** that sits just on the side that must *not* trigger the rule. If the engine flags a control case, the engine is wrong.
- The generator is deterministic: with seed 42 it always produces 1,035 events, the same on Windows and Linux. Tests can rely on exact counts.
- Test names describe the behavior they check (`test_sixth_transfer_in_ten_minutes_is_held`), so a failure line already says what broke.
