# Deploy to AWS with Terraform

This page takes you from a machine without any AWS tools to a full test of the development environment in AWS: create it, check it, prove that the evidence bucket cannot be deleted, and destroy it. [Terraform](../architecture/terraform.mdx) explains what the code creates and why; this page is only the how.

A full session lasts about 40 minutes and costs less than USD 0.30 (the two NAT Gateways and RDS Multi-AZ cost about USD 0.15 an hour together). **Always finish with `terraform destroy`:** the NAT Gateways and RDS charge by the hour even with no traffic.

The commands are for PowerShell on Windows. Run them one at a time.

## 1. Install the AWS CLI and Terraform

```powershell
winget install Amazon.AWSCLI
```

```powershell
winget install Hashicorp.Terraform
```

Close the terminal and open a new one, so it sees the new programs. The terminal inside VS Code may keep the old path until you close VS Code completely. Then check both:

```powershell
aws --version
```

```powershell
terraform -version
```

Terraform must be 1.9 or later.

## 2. Create an IAM user for Terraform

Terraform never uses the root account. Sign in to the [AWS console](https://console.aws.amazon.com/) with the root account only for these steps.

1. **IAM → Users → Create user.** Name it `<your-name>-terraform` (for example `jorge-terraform`). Leave "Provide user access to the AWS Management Console" unchecked: this user only runs commands.
2. **Set permissions → Attach policies directly**, and check **`PowerUserAccess`**. It allows everything except managing IAM. Create the user.
3. Open the user → **Permissions → Add permissions → Create inline policy → JSON**. Paste the whole content of [`infra/terraform/terraform-user-policy.json`](https://github.com/SecurePay-Riwi/SecurePay/blob/main/infra/terraform/terraform-user-policy.json) and name the policy **`securepay-terraform-iam`**. It only lets the user create roles and users whose name starts with `securepay-`, the GitHub OIDC provider, and attach the one managed policy the Lambdas use.

The user must end with exactly these two: `PowerUserAccess` and `securepay-terraform-iam`. Other policies such as `AmazonEC2FullAccess` are already covered by `PowerUserAccess` and can be removed.

## 3. Create the access key and configure the CLI

1. In the user: **Security credentials → Access keys → Create access key → Command Line Interface (CLI)**. Accept the warning and create it.
2. AWS shows the **secret access key only once**. Keep this tab open until the next step finishes. Never paste the key in a file in the repository, in a chat or in a screenshot.
3. Configure the CLI with that key:

   ```powershell
   aws configure
   ```

   It asks for four values: the Access Key ID, the Secret Access Key, the region **`us-east-2`** and the output format (`json`).

4. Check that the CLI signs in as the new user. The `Arn` must end with `user/<your-name>-terraform`:

   ```powershell
   aws sts get-caller-identity
   ```

   `InvalidClientTokenId` means the key was copied wrong: run `aws configure` again. The key is saved in `%USERPROFILE%\.aws\credentials`, outside the repository; Terraform reads it from there.

## 4. Create the environment

Everything runs in `infra\terraform\envs\dev`:

```powershell
cd infra\terraform\envs\dev
```

1. The first time, create your variables file:

   ```powershell
   Copy-Item terraform.tfvars.example terraform.tfvars
   ```

   Open `terraform.tfvars` and fill in `owner` (just your name, free text that goes in the `owner` tag) and `budget_emails` (your real email: the budget alerts arrive there). Git ignores this file.

2. Download the providers:

   ```powershell
   terraform init
   ```

3. See what will be created. It must say `Plan: 139 to add, 0 to change, 0 to destroy`:

   ```powershell
   terraform plan
   ```

4. Create it and type `yes`. RDS takes 10 to 15 minutes:

   ```powershell
   terraform apply
   ```

   It ends with `Apply complete! Resources: 139 added`. From this moment it costs money.

**If `apply` fails,** Terraform stops and prints `Error:` with the resource and the AWS message. What it created before the error stays in the state: fix the cause and run `terraform apply` again (it only creates what is missing; a resource that failed halfway is replaced), or run `terraform destroy`.

## 5. Check it

**Terraform matches AWS.** Right after the `apply`, this must say `No changes. Your infrastructure matches the configuration.`:

```powershell
terraform plan
```

**In the console** (region Ohio):

| Where | What you must see |
| :--- | :--- |
| VPC → Your VPCs | `securepay-dev-vpc`, `10.0.0.0/16` |
| VPC → Subnets | 6: `securepay-dev-public-a/b`, `-app-a/b`, `-data-a/b` |
| VPC → NAT gateways | 2, "Available" |
| VPC → Security groups | 6 `securepay-dev-sg-*`; `sg-rds` and `sg-cache` with no outbound rules |
| IAM → Roles | 21 `securepay-dev-*` |
| S3 | 4 buckets `securepay-dev-*-<account>`; in the evidence bucket, Properties → Object Lock "Enabled" |
| RDS → Databases | `securepay-dev-db`, Multi-AZ "Yes", "Publicly accessible: No" |
| Systems Manager → Parameter Store | 7 parameters under `/securepay/dev/rds/` |
| Billing → Budgets | `securepay-dev-budget`, USD 5 |

**Tags.** In **Resource Groups → Tag Editor**, choose the regions `us-east-2` **and** `Global` (IAM roles are global and do not show under Ohio), all resource types, and the tag `project` = `securepay`. Every resource must also carry `environment = dev`, `owner = <your name>` and `managed_by = terraform`. The pieces that are not resources of their own (route table associations, policy attachments, bucket settings) cannot carry tags; they cost nothing and disappear with their resource.

## 6. Prove that evidence cannot be deleted

The evidence bucket has Object Lock. In dev it has no default retention, so `destroy` works the same day; instead, you upload a test object locked for 5 minutes in COMPLIANCE mode. Decide the time before uploading: COMPLIANCE can be extended but never shortened.

1. Get the bucket name (the one ending in `-evidence-<account>`):

   ```powershell
   terraform output bucket_names
   ```

2. Create a test file, compute the lock date (5 minutes from now, in UTC) and upload it. Replace `<evidence-bucket>` with the name from step 1:

   ```powershell
   "test evidence" | Out-File test.txt
   ```

   ```powershell
   $until = (Get-Date).ToUniversalTime().AddMinutes(5).ToString("yyyy-MM-ddTHH:mm:ssZ")
   ```

   ```powershell
   aws s3api put-object --bucket <evidence-bucket> --key test.txt --body test.txt --object-lock-mode COMPLIANCE --object-lock-retain-until-date $until
   ```

   It returns a `VersionId`. Each upload creates another version, and each version keeps its own lock.

3. Try to delete it with that `VersionId`. **It must fail** with `AccessDenied ... protected by object lock`:

   ```powershell
   aws s3api delete-object --bucket <evidence-bucket> --key test.txt --version-id <VersionId>
   ```

4. To see until when a version is locked (the time is in UTC, `+00:00`):

   ```powershell
   aws s3api get-object-retention --bucket <evidence-bucket> --key test.txt --version-id <VersionId>
   ```

Delete the local `test.txt` so it does not end up in a commit.

## 7. Destroy it

Once the lock of the last uploaded version has passed, destroy everything and type `yes`. RDS takes another 10 to 15 minutes:

```powershell
terraform destroy
```

It ends with `Destroy complete! Resources: 139 destroyed`. The buckets are emptied first, all versions included. If a version is still locked, only the evidence bucket fails: wait and run `terraform destroy` again.

**Check that nothing is left.** This must print nothing:

```powershell
terraform state list
```

In the console, NAT gateways must show "Deleted", **EC2 → Elastic IPs** must be empty (an address left alone keeps charging) and **RDS → Databases** must be empty. Deleted NAT Gateways and databases can still appear for up to an hour, and Tag Editor may list them for a while; they no longer cost anything.

**Cost.** The bill does not show what is running right now: **Billing → Cost Explorer** shows each day about 24 hours later (group by service, daily). To filter future tests by `project = securepay`, activate the `project` tag once in **Billing → Cost allocation tags**; it counts only from the day it is activated.

## Rules

- **One computer.** The state (`terraform.tfstate`) stays in `envs\dev` on your computer and git ignores it. Always run `apply` and `destroy` from the same computer: another one has no state and does not know what exists.
- **Never share the state.** It holds the RDS passwords in plain text.
- **Never commit** `terraform.tfvars`, `terraform.tfstate` or anything with keys. Do commit `.terraform.lock.hcl` when `terraform init` adds hashes to it.

## Errors already seen

| Error | Cause | What to do |
| :--- | :--- | :--- |
| `aws` or `terraform` is not recognized | The terminal was open before the install | Open a new terminal (close VS Code completely if it is its terminal) |
| `InvalidClientTokenId` | Access key copied wrong | `aws configure` again |
| `FreeTierRestrictionError: backup retention period` | An account on the AWS free plan accepts at most 1 day of RDS backups | Already handled: dev uses `database_backup_retention_days = 1`. If a similar error mentions Multi-AZ, add `database_multi_az = false` to `terraform.tfvars` |
| `AccessDenied ... protected by object lock` on `destroy` | A test object is still locked | Wait until its retain-until date and run `destroy` again |
