# Local setup

This page takes you from an empty machine to a running decision engine. It follows the same steps as the repository `README.md`.

## Requirements

| Tool | Why |
| :--- | :--- |
| [uv](https://docs.astral.sh/uv/getting-started/installation/) | Python package and environment manager. It installs Python 3.12 if you do not have it. |
| [Docker Desktop](https://www.docker.com/products/docker-desktop/) | Runs PostgreSQL, Valkey and LocalStack. |
| A free [LocalStack](https://app.localstack.cloud) account (Hobby plan) | Since March 2026 LocalStack images need an auth token. |
| Git | To clone the repository. |
| PostgreSQL 16 (optional) | Only if you prefer an installed PostgreSQL over the one in Docker Compose. |

## 1. Clone and install dependencies

```bash
git clone https://github.com/SecurePay-Riwi/SecurePay.git
cd SecurePay
uv sync
```

`uv sync` creates `.venv` and installs exactly the versions pinned in `uv.lock`, including the dev group (pytest) and the spark group (pyspark 4.1.x, for the reconciliation match; the Docker image leaves both out). The match tests also need Java 17 or later (`java -version`); without it they are skipped. The `load` group (Locust, for the [load test](./load-test.mdx)) is not installed by default: `uv sync --group load`. You do not need to activate the environment: every command runs with `uv run`.

## 2. Create the `.env`

```bash
cp .env.example .env
```

<Callout title="Keep your token private" type="warning">
Paste your LocalStack token (*Settings → Auth Tokens* in app.localstack.cloud) and check `DATABASE_URL`. The token goes only in your `.env`, never in the repository.
</Callout>

```env
DATABASE_URL=postgresql://pagoseguro:pagoseguro@localhost:5433/pagoseguro
VALKEY_URL=redis://localhost:6379/0
LOCALSTACK_AUTH_TOKEN=ls-...
```

:::tip[Port 5433 or 5432]
The Compose PostgreSQL listens on **5433** on your machine so it does not collide with an installed PostgreSQL; `.env.example` comes with 5432, the installed one, so change it if you use Compose's. The containers of the stack always use Compose's database (`postgres:5432` inside the Docker network). What you run on your machine with `uv run` (pytest, the seed) uses `DATABASE_URL`: if you have both, the tests go to the one in `DATABASE_URL`, not to the one the stack writes to.
:::

The `AWS_*` variables point to LocalStack with fake credentials (`test`) on purpose. In AWS they are not set: the engine and the Lambdas use their IAM role. Every variable is explained in [Configuration](../reference/configuration.mdx).

## 3. Start the local services

With Docker Desktop open:

```bash
docker compose up -d
docker compose ps
```

The three services must end up `healthy`:

| Service | Image | Port | Used for |
| :--- | :--- | :--- | :--- |
| `postgres` | `postgres:16` | 5433 | Master data (users, accounts, devices, merchants, lists). |
| `valkey` | `valkey/valkey:8` | 6379 | Idempotency keys and the velocity history. ElastiCache in AWS. |
| `localstack` | `localstack/localstack:2026.09.1` | 4566 | SNS, SQS, S3 and DynamoDB. |

LocalStack is only `healthy` after `infra/localstack/init/01_messaging.py` created the `decisiones` topic, the `casos`, `historial` and `analitica` queues (each with its `-dlq`) and the `pagoseguro-datalake` bucket, `02_sources.py` created the `pagoseguro-proveedor-listas` bucket for the [restricted list service](../components/restricted-list.mdx), and `03_exchange_rates.py` created the `pagoseguro-exchange-rates` table for the [exchange rates](../components/exchange_rates.mdx). LocalStack keeps nothing when it stops: every start recreates everything empty.

| Command | Effect |
| :--- | :--- |
| `docker compose stop` | Stops the services and keeps the PostgreSQL data. |
| `docker compose down` | Removes the containers and keeps the PostgreSQL data. |
| `docker compose down -v` | Removes the containers **and** the PostgreSQL data. |

:::note
If you used the standalone `pagoseguro-valkey` container before the Compose existed, stop it first (`docker stop pagoseguro-valkey`): it uses the same port 6379.
:::

## 4. Load the seed

The seed lives in the [`securepay-seed`](https://github.com/SecurePay-Riwi/securepay-seed) repository, cloned next to `SecurePay`:

```bash
cd ../securepay-seed
cp .env.example .env
uv sync
uv run python -m securepay_seed.seed
```

In `dev` mode it creates 100 users, 100 accounts, 150 devices (4 of them shared), 50 merchants and 20 people in the restricted list (5 of them are customers). Check it:

```bash
docker compose exec postgres psql -U pagoseguro -d pagoseguro -c "SELECT COUNT(*) FROM usuarios;"
```

<Callout title="Verify the seed" type="tip">
It must return `100`. More options (volumes, defects, reset) in [Seed](../components/seed.mdx).
</Callout>

:::caution[Reseed after pulling the generator changes]
On October 13, 2026 the seed stopped taking dates from Faker (Faker gives different dates on Windows and Linux). If your database was loaded before that, reload it once with `SEED_RESET=true`.
:::

## 5. Start the decision engine

```bash
uv run uvicorn services.decision_engine.main:app --reload
```

The API is at http://localhost:8000 and its interactive documentation at http://localhost:8000/docs. It needs PostgreSQL and Valkey; without Valkey, `POST /transactions` answers `503`.

## 6. Start the consumers (optional)

In another terminal:

```bash
uv run python -m services.consumers
```

They read the three queues in LocalStack and call the same handlers that will run as Lambdas in AWS. See [Consumers](../components/consumers.mdx).

## Full ecosystem with Docker Compose (MAG-31 / MAG-32)

To run the full stack, clone the satellite repositories beside SecurePay: `securepay-seed`, `securepay-generator`, `securepay-csv` and `securepay-apis`. Open Docker Desktop, create `.env` from `.env.example`, and set your personal `LOCALSTACK_AUTH_TOKEN`. Never commit the `.env` file or tokens.

From the SecurePay root:

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps
```

Compose builds and coordinates PostgreSQL, Valkey, LocalStack, the seed, the cache loader, decision engine, restricted-list API, consumers, transaction generator and partner statements. The seed, the cache loader and the generator are one-shot jobs: the cache loader copies accounts, merchants and the restricted list into Valkey after the seed, and the engine starts after it (it never reads PostgreSQL). Valkey keeps nothing when it restarts: run `docker compose up cache-loader` again, or the engine answers with default decisions. The seed uses `SEED_RESET=true`, so this setup regenerates development data and must not be run against data you need to preserve.

- Decision engine: http://localhost:8000/health
- Restricted-list API: http://localhost:8001/health

Valkey starts empty on every `up` (no persistence), so no `FLUSHDB` is needed between runs. The engine settings (history, timeout, mule) are read from `.env`, with the same defaults as `.env.example`.

To stop containers while retaining named volumes, run `docker compose down`. To delete the persisted data too, run `docker compose down -v`. Kaggle download is optional and requires `KAGGLE_API_TOKEN` in `.env`.

## Image size before and after (topic 3) {/* #image-size */}

Every image we build is smaller than the same image without the optimizations: 68 % to 92 % less on disk. Measured on November 8, 2026 with Docker Desktop on Windows, at the commit shown for each repository.

| Image | Commit | Before (MB) | After (MB) | Saved | Compressed after (MB) |
| --- | --- | --- | --- | --- | --- |
| `SecurePay` (engine, consumers, APIs, Lambdas) | `e310a93` | 8,211 | 675 | 92 % | 172 |
| `securepay-seed` | `922d01e` | 1,750 | 507 | 71 % | 133 |
| `securepay-apis` | `4cdd333` | 1,743 | 459 | 74 % | 127 |
| `securepay-generator` | `f3831d1` | 1,727 | 471 | 73 % | 129 |
| `securepay-csv` | `1cdacab` | 1,634 | 516 | 68 % | 137 |

"Before" and "after" are the size on disk (`docker image inspect`, `Size`); "compressed" is the content Docker reports for the image, close to what is pushed to ECR.

**Before** is `infra/docker/Dockerfile.baseline`, built on each repository: what the image would be without the optimizations.

- The full `python:3.12-bookworm` image instead of a slim one.
- Every dependency group: the dev tools (pytest, ruff) and, in `SecurePay`, pyspark.
- No `.dockerignore` except for secrets (`.env`, Terraform state and `tfvars`), so the local `.venv`, caches and generated data go into the image too. That is most of `SecurePay`'s 8 GB.

**After** is each repository's own `Dockerfile` and `.dockerignore`, unchanged.

- The slim `ghcr.io/astral-sh/uv:python3.12-bookworm-slim` base.
- Only the main dependencies (`uv sync --no-dev`; `SecurePay` adds `--no-default-groups` to leave pyspark out, about 300 MB, which Glue brings itself).
- A `.dockerignore` that keeps out `.venv`, caches, generated and Kaggle data, the documentation site and the Terraform state.
- In `SecurePay`, `pyproject.toml` and `uv.lock` are copied before the code, so a code change does not reinstall the dependencies.

To measure it again (Docker running, the five repositories side by side, from the root of `SecurePay`):

```powershell
powershell -ExecutionPolicy Bypass -File infra\docker\measure-image-sizes.ps1
```

It builds ten images tagged `size-<repo>:before` and `size-<repo>:after` (10 to 20 minutes the first time), prints the table and writes `infra/docker/sizes.csv` (ignored by git). Remove them afterwards with `docker image rm $(docker image ls "size-*" -q)`.
