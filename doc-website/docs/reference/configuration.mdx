# Configuration

All configuration comes from environment variables, loaded from `.env` with `python-dotenv`. Each repository has its own `.env.example` with only the variables it uses: copy it to `.env` in that repository; the defaults work for local development. Never commit `.env`.

| Repository | Sections on this page |
| :--- | :--- |
| `SecurePay` | Database, Decision engine, Rules API, Cases, Messaging and Data Lake, Docker Compose |
| `securepay-seed` | Database, Seed, Kaggle ETL, AWS variables (to export the restricted list to S3) |
| `securepay-generator` | Database, Transaction generator |
| `securepay-csv` | Kaggle datasets, Partner statements, AWS variables |
| `securepay-apis` | Restricted list service, Exchange rates, AWS variables |

The AWS variables (`AWS_ENDPOINT_URL`, `AWS_DEFAULT_REGION` and the fake keys) are described under Messaging and Data Lake and work the same in every repository.

## Database

| Variable | Example | What it does |
| :--- | :--- | :--- |
| `DATABASE_URL` | `postgresql://pagoseguro:pagoseguro@localhost:5433/pagoseguro` | PostgreSQL connection for what runs on your machine (pytest, the seed). Port 5433 for the Compose database, 5432 for an installed one (the `.env.example` default). The containers ignore it and use `postgres:5432`. |
| `DATABASE_USER` | `cases_consumer` | AWS only. When set, `DATABASE_URL` is ignored and the URL is built from this user, the password read from `DATABASE_PASSWORD_PARAMETER` and the variables below (MAG-361, [Database users](../architecture/security.mdx#database-users)). |
| `DATABASE_PASSWORD_PARAMETER` | `/securepay/dev/rds/cases_consumer` | AWS only. Name of the Parameter Store `SecureString` with the user's password; the component's role may read only its own. |
| `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME` | RDS endpoint, `5432`, `securepay` | AWS only. Where the database is. |
| `DATABASE_SSLMODE` | `require` | AWS only. TLS mode of that connection; RDS requires TLS. Only the tests against a local PostgreSQL set `disable`. |
| `CREATE_SCHEMA` | `true` | `false` in AWS: `db-bootstrap` creates the tables there and the components skip `create_schema()`, which needs to own the tables. |
| `DATABASE_PARAMETER_PATH` | `/securepay/dev/rds` | `db-bootstrap` only: parent path of the component passwords it gives to each user. |

## Decision engine

| Variable | Default | What it does |
| :--- | :--- | :--- |
| `VALKEY_URL` | `redis://localhost:6379/0` | Valkey connection (ElastiCache in AWS). |
| `VALKEY_CLUSTER` | `false` | `true` uses the cluster client. ElastiCache Serverless only accepts the cluster protocol, so Terraform sets it in AWS; local Valkey is a single node. |
| `IDEMPOTENCY_TTL_SECONDS` | `3600` | How long a decision is returned to resends. |
| `HISTORY_OUT_HOURS` | `24` | Outgoing history kept per account (`out:{account}`). At least 24: the longest velocity and splitting windows the catalog accepts. |
| `HISTORY_OUT_LIMIT` | `100` | Newest outgoing movements the rules read. At least 100: the highest velocity `limit` (99) and splitting `min_transactions` (100) the catalog accepts. |
| `HISTORY_IN_MINUTES` | `60` | Incoming history kept per account (`in:{account}`), for the mule rule. At least 60, the longest mule window the catalog accepts. |
| `HISTORY_DEVICE_DAYS` | `30` | How long an account stays on a device's history (`dev:{device}`), for the shared device rule. At least 30, the longest window the catalog accepts. |
| `HISTORY_SECURITY_MINUTES` | `60` | Security events kept per account (`sec:{account}`), for the account takeover rule (1 hour). |
| `DECISION_TIMEOUT_MS` | `120` | How long the engine waits for the rules before applying the default decision (RN-01). Below 200 ms so the answer and the network still fit. |
| `SLOW_DECISION_MS` | `150` | A decision at least this slow is written to the `securepay.decisions` log as one JSON line, like every HOLD, REJECT or default decision (HU-59). The CloudWatch metric filters and saved queries read those lines. |
| `DECISION_WORKERS` | `40` | Threads that evaluate the rules. A timed-out evaluation keeps its thread until it ends. |
| `RULES_REFRESH_SECONDS` | `1` | How often the engine checks Valkey for a new catalog version published by the [rules API](../components/rules-api.mdx). A change reaches the decisions within this time. |
| `RATES_TABLE` | `pagoseguro-exchange-rates` | Sprint 5 (HU-42): DynamoDB table of the daily exchange rates that [securepay-apis](../components/exchange_rates.mdx) loads. In AWS Terraform sets it to `securepay-<env>-exchange-rates`. Loaded in memory by the engine at startup ([Exchange rate of the day](../components/decision-engine.mdx#exchange-rate-of-the-day)). |
| `RATES_REFRESH_SECONDS` | `3600` | Sprint 5 (HU-42): seconds between the engine's reloads of the rates table. |
| `REFDATA_TTL_HOURS` | `48` | Sprint 5 (HU-67): hours the accounts and merchants stay in the cache; every load of the cache loader renews them, so what is deleted at the source disappears on its own. |

Rule thresholds (velocity, mule account, shared device, the default decision limit) are not environment variables: they live in the rule catalog, see [Rules and the catalog](../components/decision-engine.mdx#rule-catalog).

See [Decision engine](../components/decision-engine.mdx).

## Rules API

In `SecurePay` (`services/rules_api/`). It uses `DATABASE_URL` (its tables `rules` and `rule_catalog_versions`, created at startup) and `VALKEY_URL` (where it publishes the catalog); it has no variables of its own. See [Rules API](../components/rules-api.mdx).

## Cases

In `SecurePay`: the cases API (`services/cases_api/`), the consumers and the alerts task (`services/alerts/`). All three use `DATABASE_URL` and create the case tables at startup (in AWS, `db-bootstrap` creates them and `CREATE_SCHEMA=false`). See [Cases](../components/cases.mdx).

| Variable | Default | What it does |
| :--- | :--- | :--- |
| `CASES_API_PORT` | `8003` | Port of the cases API outside Compose's network. |
| `CASE_DUE_MINUTES` | `240` | RN-09: a case not resolved in this many minutes is escalated. Lower it (e.g. `2`) for a demo. |
| `ACCOUNT_HISTORY_DAYS` | `30` | Days of history per account in `account_transactions` (HU-28). |
| `ALERTS_INTERVAL_SECONDS` | `60` | Local only: seconds between runs of `python -m services.alerts`. In AWS, EventBridge runs it every 5 minutes. |
| `OPS_ALARMS_TOPIC` | `ops-alarms` | SNS topic of the technical team's alarms, where the 06:30 reconciliation check warns: a name or an ARN. In AWS: the ARN of `securepay-<env>-ops-alarms`. |
| `BUSINESS_ALERTS_TOPIC` | `business-alerts` | SNS topic of the business alerts (supervisor and compliance): a name or an ARN. In AWS: the ARN of `securepay-<env>-business-alerts` (with a name the task calls `create_topic` to get the ARN). |
| `EVIDENCE_BUCKET` | `pagoseguro-evidence` | RN-12: bucket with Object Lock where a resolved case's evidence is archived (HU-32). In AWS: the `evidence` bucket of Terraform. |
| `EVIDENCE_RETENTION_DAYS` | `3650` | RN-12: how long each evidence object stays locked (COMPLIANCE), 10 years. A decimal: dev in AWS and the tests use `0.0035` (about 5 minutes), because a COMPLIANCE lock can never be shortened and 3650 would keep the bucket, and `terraform destroy`, blocked for 10 years. |

## Reconciliation

In `SecurePay` (`services/reconciliation/`, Sprint 5). `uv run python -m services.reconciliation --day YYYY-MM-DD` also uses `DATABASE_URL` (its tables are created at the start). See [Reconciliation](../components/reconciliation.mdx).

| Variable | Default | What it does |
| :--- | :--- | :--- |
| `RECON_DATA_DIR` | `generated/reconciliation` | Root of `curated/` (the records read and the match of each day). Local runs only, ignored by git; in AWS, `s3://<datalake bucket>`. |
| `STATEMENTS_SOURCE` | `../securepay-csv/generated/extractos` | Where the partners' files are read: a local folder laid out like `generated/extractos/`, or `s3://<datalake bucket>/raw/extractos`. |
| `DECISIONS_SOURCE` | `s3://pagoseguro-datalake/raw/decisiones` | The engine's decisions as the analytics consumer writes them (locally in LocalStack), one folder `fecha=YYYY-MM-DD` per day. |
