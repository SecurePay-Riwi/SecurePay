# How the Documentation Site Was Built

This document explains how the documentation site you are reading right now was created, integrated into the main project repository, and deployed automatically to GitHub Pages.

The entire setup is versioned alongside the source code, so documentation and code evolve together. No external hosting, no manual deployments, no separate repository.

---

## Overview

The documentation site is built with **Docusaurus 3**, a static site generator based on React and Markdown. It lives inside the main repository under the `doc-website/` folder.

Key components:

- **Site generator:** Docusaurus 3 — builds the static site from Markdown files.
- **Runtime:** Node.js 20 — required to build and serve the site.
- **Package manager:** npm — manages dependencies.
- **Hosting:** GitHub Pages — serves the generated static files.
- **CI/CD:** GitHub Actions — builds and deploys on every push.

## Step 1: Scaffold the Docusaurus Site

Docusaurus is initialized with the official scaffolding tool:

```bash
npx create-docusaurus@latest doc-website classic --typescript
```

This creates a new folder `doc-website/` with:

- A `classic` preset (docs + blog + custom pages)
- TypeScript configuration
- Default example content (which we later removed, including the blog, which is disabled with `blog: false`)

---

## Step 2: Configure the Site

The main configuration lives in `doc-website/docusaurus.config.ts`. The four fields that must be adjusted for GitHub Pages are:

**File:** `doc-website/docusaurus.config.ts`

```typescript
const config: Config = {
  title: 'SecurePay Docs',
  url: 'https://securepay-riwi.github.io',
  baseUrl: '/SecurePay/',
  organizationName: 'SecurePay-Riwi',
  projectName: 'SecurePay',
  onBrokenLinks: 'throw',
  // ...
};
```

Field breakdown:

- **`url`** — Base URL of the GitHub Pages domain. Format: `https://<org>.github.io`
- **`baseUrl`** — Subpath where the site is served. Format: `/<repo>/` (with leading and trailing slash)
- **`organizationName`** — GitHub organization that owns the repository.
- **`projectName`** — Repository name.

:::warning
The `baseUrl` must match the repository name exactly, including capitalization, and must start and end with a slash. Otherwise, assets and internal links will return 404 errors on the deployed site.
:::

---

## Step 3: Add the `.nojekyll` File

GitHub Pages uses Jekyll by default, which ignores files and folders starting with an underscore. Docusaurus generates assets inside `_next/`, so we need to disable Jekyll processing:

```bash
touch doc-website/static/.nojekyll
```

This empty file tells GitHub Pages to serve the site as-is, without any Jekyll transformation.

---

## Step 4: Add a `.gitignore` for the Site

Docusaurus generates build artifacts and installs dependencies that must not be committed.

**File:** `doc-website/.gitignore`

```gitignore
node_modules/
.docusaurus/
build/
.DS_Store
```

What each entry means:

- **`node_modules/`** — Installed dependencies (regenerated by `npm ci`).
- **`.docusaurus/`** — Docusaurus internal cache.
- **`build/`** — Generated static site (created during CI).
- **`.DS_Store`** — macOS metadata.

## Step 5: Create the GitHub Actions Workflow

The deployment is fully automated with a single workflow file. It runs on every push to `main` that modifies anything inside `doc-website/`.

**File:** `.github/workflows/doc-site.yml`

```yaml
name: Deploy Docs to GitHub Pages

on:
  push:
    branches: [main]
    paths:
      - 'doc-website/**'
      - '.github/workflows/doc-site.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ./doc-website
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: 'doc-website/package-lock.json'

      - name: Install dependencies
        run: npm ci

      - name: Build Docusaurus
        run: npm run build

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./doc-website/build

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### How the Workflow Works

- **`on.push.paths`** — Only triggers when files inside `doc-website/` change.
- **`permissions`** — Minimal permissions required to deploy to Pages.
- **`concurrency`** — Prevents two deployments from running at the same time.
- **`job.build`** — Installs dependencies, builds the static site, uploads it as an artifact.
- **`job.deploy`** — Downloads the artifact and publishes it to GitHub Pages.
- **`working-directory`** — Runs all commands inside `doc-website/` instead of the repository root.

---

## Step 6: Enable GitHub Pages

Once the workflow file is pushed, GitHub Pages must be enabled in the repository settings.

1. Go to the repository on GitHub.
2. Navigate to **Settings → Pages**.
3. Under **Build and deployment → Source**, select **GitHub Actions**.
4. The next push (or manual re-run) will deploy the site.

:::tip
If the workflow fails with an error like `Pages not enabled`, it means this step was skipped. Enable it and re-run the workflow.
:::

---

## Step 7: Verify the Deployment

After the first successful run:

1. Open the **Actions** tab in the repository.
2. The workflow `Deploy Docs to GitHub Pages` should display a green check.
3. The site is live at:

```text
https://securepay-riwi.github.io/SecurePay/
```

## Updating the Documentation

Updating the site is a simple three-step process.

### 1. Edit the Markdown files

All content lives in `doc-website/docs/`. Edit any `.md` or `.mdx` file.

### 2. Preview locally (recommended)

```bash
cd doc-website
npm install
npm run start
```

The site opens at `http://localhost:3000/SecurePay/` and reloads automatically on every save.

### 3. Push the changes

```bash
git add doc-website/
git commit -m "docs: update architecture section"
git push origin main
```

GitHub Actions detects the change and redeploys the site in 1-2 minutes.

## Troubleshooting

### Build fails with "Docusaurus found broken links"

Docusaurus fails the production build if any Markdown file links to a non-existent path. The error message lists every broken link with its source file.

**Solution:** Fix the link, or remove the file that contains it.

```text
- Broken link on source page path = /SecurePay/docs/example:
   -> linking to ./missing-file.mdx
```

### Deployment fails with "Pages not enabled"

GitHub Pages has not been enabled in **Settings → Pages**. Set the source to **GitHub Actions** and re-run the workflow.

### Site loads but assets return 404

The `baseUrl` in `docusaurus.config.ts` does not match the repository name. It must be exactly `/<repo-name>/`, with leading and trailing slashes.

### Workflow does not trigger on push

The changes were made outside `doc-website/`. The workflow only triggers when files inside that folder are modified.

## Summary

Decisions made in this setup:

- **Location:** Inside the main repository (`doc-website/`) — keeps docs and code in sync.
- **Isolation:** Separate `package.json` and `node_modules` — avoids dependency conflicts with Python.
- **Deployment:** GitHub Actions → GitHub Pages — free, automated, versioned.
- **Trigger:** Push to `main` with changes in `doc-website/` — avoids unnecessary runs.
- **Build tool:** `npm ci` + `npm run build` — reproducible, deterministic builds.

The result: a documentation site that is versioned with the code, deployed automatically on every change, and served for free by GitHub Pages.
